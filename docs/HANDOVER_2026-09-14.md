- **서비스 배수 폐지.** `SERVICE_MULTIPLIER` runtime 0건.

# 예약 중복 제출 방지 (idempotency) — 2026-09-15

## 검증 결과

| 항목 | 결과 |
|---|---|
| quoteToken 보안 테스트 | 15/15 PASS |
| sequential retry | PASS |
| concurrent (SQLite) | PASS |
| **concurrent (PostgreSQL 16, 별도 연결 2개)** | **PASS** |
| PostgreSQL integration | **7/7 PASS, 0 skipped** |

PostgreSQL 동시성 테스트는 실제로 연결 2개를 열어 같은 `quote_id`로 동시에 INSERT했다.
정확히 하나만 성공하고 나머지는 `23505`로 실패했으며, DB에는 예약 1건만 남았다.
경합에서 실패한 연결로 다시 조회했을 때 성공한 예약과 같은 id가 조회되는 것까지 확인했다.

## 두 경로의 역할 구분 (중요)

**SQLite transaction serialization**
`node:sqlite`는 단일 동기 연결이라 `BEGIN`이 중첩되면
`cannot start a transaction within a transaction`으로 실패한다.
`withTransaction()`의 SQLite 분기에 직렬화 큐를 두어 이를 막는다.
**이것은 단일 프로세스 개발/테스트 환경용 보호장치이며 운영 동시성 보장 수단이 아니다.**

**운영 concurrency 보장**
PostgreSQL의 `reservations.quote_id` UNIQUE(partial index) + 경합 시 rollback 후 재조회로 처리한다.

```
동시 INSERT → 한쪽 23505
           → 해당 transaction rollback
           → 정상 connection에서 quote_id로 기존 예약 재조회
           → 동일 성공 결과 반환 (generic 500 아님)
```

aborted transaction 안에서 SELECT하지 않는다.

## 오판 방지

`isUniqueViolation()`은 PG `23505`와 SQLite `ERR_SQLITE_ERROR` + `UNIQUE constraint failed`만 인식한다.
`DB_TIMEOUT` · `ECONNREFUSED` · `42P18` · `42601` · `23502` · `23503` · `08006`은 인식하지 않는다.
cause 체인 unwrap은 depth 5 제한과 순환 참조 방지를 갖는다.

## 운영 배포 순서 (반드시 이 순서)

```
1. migration 적용
   supabase/migrations/20260915090000_reservation_idempotency.sql
2. migration 확인
   SELECT indexname FROM pg_indexes
    WHERE tablename='reservations' AND indexname='idx_reservations_quote_id';
   -- 1건이어야 한다
3. application deploy
```

**순서를 바꾸면 안 된다.** 애플리케이션이 먼저 배포되면 `quote_id` 컬럼이 없어
예약 저장이 `42703 undefined column`으로 전면 실패한다.
