# Clyn Clean 4단계 예약 프로세스 설계

## 목표

고객 예약을 6단계에서 4단계로 단순화하고, 일반청소와 사이청소의 시간 선택 정책을 분리한다. 자동예약 가능 건은 4단계 완료 직후 예약 선금 계좌까지 확인할 수 있어야 한다.

## 확정 흐름

1. **서비스**
   - 청소 종류, 주택 유형/평형 또는 집정리 패키지를 선택한다.
   - 선택 즉시 서버 견적을 표시한다.
   - 견적 요청이 겹칠 때 이전 응답이 최신 상태를 덮어쓰지 않게 한다.
   - 견적 요청 중에는 `가격을 불러오는 중...`만 표시하고 일시적인 `가격 정보를 불러올 수 없습니다.` 깜빡임을 만들지 않는다.

2. **날짜**
   - 입주청소/거주청소/집정리: 날짜 + 오전/오후 슬롯을 선택한다.
   - 사이청소: 날짜 + `퇴거 완료 예정시간` + `새 입주 예정시간`만 입력한다. 오전/오후 선택 버튼은 표시하지 않는다.
   - 사이청소는 고객 입력에서 `time_slot = all_day`로 정규화한다.
   - 새 입주 예정시간은 퇴거 완료 예정시간보다 반드시 늦어야 한다.

3. **고객정보**
   - 예약자명, 연락처, 작업지역, 상세주소, 이메일(선택), 기타 요청사항을 한 화면에서 받는다.
   - 입주청소/거주청소는 `입주 전 / 퇴거 후 / 거주 중`을 같은 고객정보 단계에서 받는다.
   - 사이청소는 퇴거/입주 시간이 이미 작업상태를 설명하므로 입주상태 선택을 숨긴다.
   - 집정리도 입주상태 선택을 사용하지 않는다.
   - 별도 `현장정보` 단계는 제거한다.

4. **확인·동의**
   - 서비스/상품, 날짜/시간, 고객정보, 총 예약금액/예약 선금/잔금을 요약한다.
   - 개인정보 및 기존 서비스 필수 동의를 같은 화면에서 받는다.
   - 자동예약 가능 건은 이 단계에서 예약을 생성하고 즉시 예약 선금 계좌를 조회해 결과 화면을 표시한다.
   - 상담 전환 건은 같은 4단계에서 개인정보 동의 후 상담접수로 종료한다.

## 사이청소 슬롯 정책

- 사이청소 예약 생성 요청은 오전/오후가 아니라 `all_day`만 허용한다.
- 서버는 사이청소를 접수하기 전에 같은 날짜 오전/오후 양쪽의 가용성을 모두 확인한다.
- 사이청소 예약이 `received` 상태로 생성되는 즉시 해당 날짜의 오전/오후를 모두 보호한다.
- 관리자 `calendar_slot_reopen_overrides` 기능으로 오전/오후를 각각 다시 열 수 있다.
- 재개방보다 실제 예약 점유가 우선한다.
- 일반 예약과 사이청소의 동시 생성 경쟁을 막기 위해 같은 날짜의 `all_day` advisory lock을 공통으로 잡은 뒤 개별 슬롯을 잠근다.

## 가격/예약금 정책

- 견적은 `price_rules(service_type, product_key)`의 독립 가격을 사용한다.
- 예약 생성 시 `deposit_amount_snapshot`도 해당 서비스×상품의 견적값으로 저장한다.
- 계좌 공개 시 기존 예약 snapshot이 있으면 다시 현재 가격표를 조회해 덮어쓰지 않는다.
- 레거시 예약에 snapshot이 없는 경우에만 해당 서비스×상품 가격표에서 예약금을 보완한다.
- 총액 = 예약 선금 + 잔금 관계를 유지한다.

## 결과 화면

- 일반 서비스는 `오전/오후`를 표시한다.
- 사이청소는 `종일` 같은 모호한 표기 대신 저장된 퇴거/입주 예정시간을 표시한다.

## 비범위

- 행정구역 master 데이터 생성/임포트는 하지 않는다.
- 관리자 서비스지역 정책은 변경하지 않는다.
- 관리자 슬롯 재개방 UI의 정책 자체는 변경하지 않는다.
- 가격표 값 자체는 변경하지 않는다.
